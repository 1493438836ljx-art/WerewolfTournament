# 狼人杀对局规则（引擎裁定规格）

本文是 `@wt/engine` 的规则规格。所有裁定由确定性代码执行（可重放审计），LLM 裁判不参与规则判定，只负责主持公告与发言内容仲裁。

## 1. 默认板型（9 人局）

| 角色 | 数量 | 阵营 |
|---|---|---|
| 狼人 werewolf | 3 | 狼人 |
| 预言家 seer | 1 | 好人（神职） |
| 女巫 witch | 1 | 好人（神职） |
| 猎人 hunter | 1 | 好人（神职） |
| 村民 villager | 3 | 好人（平民） |

角色分配：种子 RNG 洗牌座位，种子入库可审计。板型可经 `GameConfig.roleSet` 扩展（如 12 人局、守卫），`playerCount` 6..12。

## 2. 对局流程

```
游戏开始
 └─ 第 1 夜：狼人刀人 → 预言家查验 → 女巫用药
     └─ 黎明：结算死亡 → 公布死讯（无死因）→ 猎人枪判定 → 夜间遗言(仅第1夜) → 胜负检查
         └─ 第 1 天：轮流发言 → 投票 → [平票PK → 再投票] → 放逐 → 出局遗言 → 猎人枪判定 → 胜负检查
             └─ 第 2 夜 → …（循环直至胜负判定）
```

## 3. 夜晚裁定

### 3.1 狼人击杀
- 每只**存活**狼人各自提交一个目标（可为 `null`=空刀）
- 汇总：**多数决**；平票取**座位号最小的存活狼**的选择
- 目标必须是存活非狼座位（狼不自刀，默认板型无守卫）

### 3.2 预言家查验
- 每晚查验一名任意存活座位（可重复验已验过的人，平台在 `unchecked` 中只提示未验的）
- 返回阵营：狼人 → `wolf`，其余 → `human`（好人神职与平民不可区分）

### 3.3 女巫
- 解药/毒药各一瓶，全场各一次
- 女巫在狼刀锁定后行动，**知道今晚被刀的是谁**（`killed_tonight`）
- 首夜可以自救（`firstNightSelfSave: true`）；此后不可自救（`can_self_heal` 会如实告知）
- **同一夜双药不可同用**；被毒者不可被同夜解药救（刀、毒若同夜命中同一目标，按死亡结算）
- 行动顺序上解药先于毒药结算，但两药目标互不影响（毒任何存活者，包括自己）

## 4. 死亡结算与猎人

黎明结算顺序：
1. 被刀且未被救者死亡（cause: `wolf`）
2. 被毒者死亡（cause: `poison`）
3. 公布死讯（只公布谁死了，不公布死因与顺序）
4. **猎人**：被刀或被放逐死亡时可翻牌开枪带走一名存活者；**被毒死不可开枪**
   （枪杀者死亡无遗言；被枪杀者若有遗言权按其死因规则处理——被枪杀视为无遗言）
5. 每次死亡（含枪杀）后立即检查胜负

## 5. 白天裁定

- **发言**：从死讯相关位置起顺时针（第 1 天若无死讯则从随机锚点起，种子决定）；每人一轮，字数 ≤ `speech_char_limit`
- **投票**：所有存活者各投一票（不可弃票，`abstain_allowed=false`），得票最高者被放逐；票型逐一公开
- **平票 PK**：并列最高者进入 PK 辩词（各一轮）；**PK 者不参与再投票**，其余存活者对 PK 者再投票；仍平 → 当日平安日（无人出局）
- **遗言**：白天被放逐必有遗言；夜晚死亡**仅第 1 夜**有遗言；被枪杀无遗言

## 6. 胜负判定（屠边制默认）

好人胜：**所有狼人死亡**
狼人胜（任一即胜）：
- 屠边：所有神职死亡 **或** 所有平民死亡
- 或 存活狼人数 ≥ 存活好人数

`win_condition: 'kill_all'`（屠城制）时狼人胜条件仅为「存活狼人数 ≥ 存活好人数」。

检查时机：每次死亡结算后（黎明、枪杀、放逐、取消资格）。胜负判定后游戏立即结束，全员翻牌。

## 7. 超时与违规（引擎强制，保证比赛流畅）

| 动作 | 超时默认 |
|---|---|
| 狼人刀 | 击杀 `kill_targets` 中第一个非 null 目标 |
| 预言家 | 随机查验 `unchecked` 之一（种子决定） |
| 女巫 | 不用药（heal=false, poison=null） |
| 猎人 | 不开枪 |
| 发言 | 文案「（超时未发言）」 |
| 投票 | 弃权（若禁止弃权则投第一个候选） |
| 遗言 | 文案「（无遗言）」 |

- 超时记 1 次 penalty（积分 -0.1，每局上限 -1）
- 非法回复（目标不合法/引用过期请求/格式错误）：记 1 次违规并丢弃；**累计 3 次违规 → 取消该局资格**（座位立即死亡，cause=`disqualify`，不揭示角色，该 agent 所在阵营判负按实际局面继续结算——见 TOURNAMENT.md 积分细则）
- 进程崩溃：等同持续超时，按默认动作走完，正常结算胜负

## 8. 引擎保证

- **确定性重放**：全部随机性来自种子 RNG（座位分配、PK 锚点、超时默认），同一动作序列必然重放出同一事件流
- **信息隔离**：发给每个座位的事件集合由 `visibility.ts` 单一出口裁定，属性测试覆盖「座位 i 收不到座位 j 的私有信息」
- **事件流可审计**：`game_events` append-only 入库，含每个座位收到的消息副本
